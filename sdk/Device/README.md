# Experimental Centerpiece device source target

This target is separate from the desktop C++ preview in `Unreal/`. It is prepared for Unreal **4.27**, Android ASTC, the `/Game/map/M_EntryPoint` entry map and chunk **1337**. It does not override the host's GameInstance. Its generated runtime assets use Engine classes and the reflected `SkinApi` declarations; our new desktop C++ scene actor is intentionally not a runtime dependency.

**Status: compiled and exercised with Unreal 4.27.2; device verification is still in progress.** The editor plugins, generated Blueprints and Android ASTC assets have compiled and produced integrity-checked content-only PAKs. A local Blueprint VM test verifies delayed input binding, key-code/position text, independent fish motion, nearby-key flee, held-key filtering and ignored distant presses against the local API stub. These tests do not establish that the keyboard host resolves the API or renders every material correctly. The first physical calibration exposed an invalid material shader and inverted text; those issues were corrected, and a new controlled calibration is pending hardware confirmation.

The normal scene path now generates one Engine-owned Blueprint actor per layer. Its fixed material templates draw solid/gradient backgrounds, imported images, text, individually editable fish, and common procedural effects. Actors implement independent drift, swim and orbit movement; key down/up events; nearby-object flee; pulse and visibility reactions. Surface materials implement ripple, flash, heat, burst, sparkle, shockwave and lightning responses. Idle lightning and a procedural tornado are also available as layer types. A local 21-layer coverage scene, including lightning and tornado, generated, rendered and cooked successfully; this is not hardware or complete visual-parity verification. Analog event repetitions are filtered into down/up edges, and duplicate preview pointer/key reactions are combined for physical keys. No call to the editor builder is present in generated runtime graphs.

Fish and moving objects flee from the position captured when the key is pressed. Static backgrounds ignore an all-layer flee rule; an explicitly targeted stationary image or text layer can flee. Native movement uses smooth Blueprint interpolation and original mobile materials, rather than a pixel-identical recording of the browser preview. Text uses a packaged Engine distance-field font, so desktop font choices and emoji coverage differ. Drawing meshes, font pages and materials are included as `/Game/Companion` content rather than assuming those optional assets exist in firmware.

Masks, timeline keyframes, unsupported blend modes, non-key event sources and scene-specific effects without a native renderer fail before assets are created. A layer currently supports up to 32 native reactions. The legacy 11-scene collection path remains a static reference with a global key-press material envelope and Atlas launch; its detailed browser geometry is not native parity.

## Input calibration

The reflected API does not document whether `HCode` is a physical index or a HID usage code. The original community template's exported Blueprint graph passes raw HCode into `GetPositionByKeyIndex`, then constructs world position `(API.x - 960, API.y - 275, 0)`. This matches the generator's centered 1920 × 550 geometry and supplies source evidence for its default coordinate conversion. The mapping from a Studio key name to HCode still requires measurement. A scene description beginning `STUDIO_NATIVE_INPUT_CALIBRATION` creates a diagnostic skin with an all-key flash/ripple and large on-screen HCode/raw-position text. Its initial status is `TEST READY | WAITING FOR INPUT`; the actor retries on Tick until a receiver is valid, binds once, then shows `TEST READY | INPUT CONNECTED`. Observe known keys on the actual device before enabling named-key filters or claiming accurate proximity.

After measurement, an optional local `project/device-input.json` can supply `keyCodes` (Studio key name to integer 0–255), `positionScaleX`, `positionScaleY`, `positionOffsetX` and `positionOffsetY`. Specific key groups are rejected when any key lacks a measured mapping. A calibration record's `verified` flag records the local calibration decision; it never sets the generated report's `deviceVerified` flag. The latter remains false until the complete cooked skin is independently tested.

## Evidence and origin

The primary reverse-engineering [write-up by nun](https://nun.tax/blog/reverse-engineering-the-centerpiece-pro/) describes how cooked Blueprints resolve host functions by reflected names. The reviewed MIT community template declares:

- `SkinApi.SkinCreatorLibrary.GetKeyEventReceiver()` returns `KeyEventReceiver`.
- `SkinApi.KeyEventReceiver.OnKeyEvent` carries `HCode` (uint8), `IsActuated` (bool), and `Percentage` (int32).
- `SetKeyEventReceiver(KeyEventReceiver*)` and `GetPositionByKeyIndex(uint8)` are also declared.

The declarations and their MIT notice are included in `SKINAPI-LICENSE.txt`. No stock skin assets, third-party uploader, credentials, ADB tools, or hardware access code is included. Empty/local stub function bodies support compiling in an editor; the host must resolve the equivalent names when loading the cooked Blueprint. That match remains to be confirmed on the actual keyboard firmware.

The reviewed template is [nuntax/centerpiece-sdk](https://github.com/nuntax/centerpiece-sdk) commit `0aed5d255f18292562fcfd85acf4973f28284fcd`. Its original input manager binds `SkinKeyEvent__DelegateSignature` from `GetKeyEventReceiver` on BeginPlay, without constructing or replacing the receiver. The companion's retry keeps that same contract while allowing delayed availability. Original Blueprint references were inspected in a separate local verification workspace and are not included in generated skins.

## Build after installing Unreal 4.27

1. Work from a fresh extracted source bundle. Keep `Device/` and `project/` beside one another.
2. Generate project files and compile the two source plugins for `Device/CenterpieceDevice.uproject`. The editor builder is an **Editor-only** module. Do not package a new native runtime module as a skin or flash an APK.
3. Open the Device project in Unreal 4.27. Run `Tools/generate_device.py` using Unreal's editor Python tools. Keep `Tools/device_materials.py` alongside it. It uses the adjacent exported scene and validated image manifest, imports textures automatically, creates fresh layer/input Blueprints and an entry map, and refuses existing target assets. It never uploads or invokes external processes.
4. Review the native scene and compile errors. A successful input Blueprint compile is recorded in `Saved/StudioDeviceGeneration.json`. Diagnostic scenes additionally run the local Blueprint VM and write `Saved/StudioNativeInputSmoke.json`; scenes with description prefix `STUDIO_NATIVE_RUNTIME_SMOKE` run nearby-flee tests and write `Saved/StudioNativeRuntimeSmoke.json`. Use `-AllowCommandletRendering -RenderOffscreen -StudioCapturePreview` without `-NullRHI` to capture the saved map at 1920 × 550 into `Saved/StudioDevicePreview.png`. These reports are not evidence that the firmware has delivered a key event. Shader failures must be rejected even when Unreal reports them as warnings and exits successfully.
5. Cook the generated content for Android (ASTC), then package only generated `/Game/Companion` assets and `/Game/map/M_EntryPoint` into a content PAK mounted at `../../../spark/Content/`. The local direct content cook and UnrealPak path have run without building an APK or requiring an NDK. SDK/NDK/JDK installation is relevant if you choose a full Android application package instead; the skin workflow never replaces the host APK. Inspect the PAK for the expected entry map, all texture/material/Blueprint references and no dependency on our desktop scene module.
6. Verify load, animation, key down/up, reconnect, switching away and back, and frame time on a controlled keyboard slot. Preserve the existing skin first. Only then mark a package ready for community download.

The companion currently prevents treating this source bundle as a cooked keyboard skin. UE5.8 cannot replace a 4.27 cook target: [Epic's asset compatibility guide](https://dev.epicgames.com/documentation/unreal-engine/unreal-engine-5-migration-guide) says newer saved assets cannot be opened in an older engine. Multiple engine versions can be installed side by side from the [Epic Launcher library](https://dev.epicgames.com/documentation/en-us/unreal-engine/install-unreal-engine).

For collection scenes without embedded photographic layers, the export includes a labeled static original-preset image as the device generator's visible fallback. It is not a capture of current edits or a native animation. The image manifest identifies these references, and the generator records their layer IDs in its report.
